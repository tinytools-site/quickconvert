How to format and validate JSON


JSON (JavaScript Object Notation) is the standard format for exchanging data between web services. It is strict: keys must be double-quoted, trailing commas are forbidden, and comments are not allowed. A single misplaced comma is enough to make an entire API request fail, which is why developers constantly need to validate and pretty-print JSON.


This tool parses your input with a real JSON parser — the same strictness your code will face. If the JSON is valid, you can beautify it with readable indentation or minify it into a single compact line for use in production. If it is invalid, you get the exact error message and character position so you can fix it quickly.


Common JSON mistakes include single quotes instead of double quotes, trailing commas after the last item in an object or array, unescaped line breaks inside strings, and comments copied from documentation. The 'Load sample' button gives you a valid example to experiment with if you are learning the format.


Everything runs locally in your browser — your data is never uploaded anywhere, which makes this safe for pasting API responses containing sensitive information. For large payloads, the minify option shrinks the text by removing all unnecessary whitespace.

    
Frequently asked questions




Is my JSON data uploaded to a server?
No. All parsing and formatting happens locally in your browser with JavaScript. Nothing you paste ever leaves your device.


Why does my JSON fail to validate?
The most common causes are single quotes instead of double quotes, a trailing comma after the last element, or unescaped special characters inside strings. The error message shows the exact position of the problem.


What is the difference between format and minify?
Format (beautify) adds indentation and line breaks so humans can read the structure. Minify removes all unnecessary whitespace to make the smallest possible file for production use. Both represent the same data.


Can I validate JSON with comments?
Standard JSON does not allow comments, so the validator will reject them. Remove // and /* */ comments before validating, or use a JSONC-aware editor if your config format needs comments.
